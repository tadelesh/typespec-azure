This doc details what emitters will generate for paging operations.

## Using next link to indicate how to get the next page

Next link is an absolute url returned by the paging operation, which indicates how to get the next page.
If the response does not return a next link, it indicates the last page of results.
Next link should be annotated in the response model with `@nextLink`.

There are two ways to indicate a paging operation with `@nextLink`:

1. Use `@list`, `@nextLink` and `@items`

<ClientTabs>

```typespec
@list op listWithPage(): UserList;

model User {
  id: string;
  name: string;
}

model UserList {
  @pageItems
  value: User[];

  @nextLink
  nextLink?: url;
}
```

```python
class User(_model_base.Model):
    id: str = rest_field()
    name: str = rest_field()

def list_with_page(self, **kwargs: Any) -> ItemPaged["_models.User"]:
    ...
```

```csharp
public virtual Pageable<User> ListWithPage(CancellationToken cancellationToken = default);
```

```typescript
export interface ListWithPageOptionalParams extends OperationOptions {}
// JS CodeGen api layer
export function listWithPage(
  context: Client,
  options: ListWithPageOptionalParams = { requestOptions: {} },
): PagedAsyncIterableIterator<User>;

// JS CodeGen classical client layer
export class TestServiceClient {
  listWithPage(
    options: ListWithPageOptionalParams = { requestOptions: {} },
  ): PagedAsyncIterableIterator<User>;
}
```

```java

```

```go

  Name string `json:"name"`

```

## Using continuation token to indicate how to get the next page

A continuation token is a string returned by a paging operation, which is used as a parameter value for the paging operation to get the next page.
If the response does not return a continuation token, it indicates the last page of results.
The request parameter that corresponds to the continuation token value in the paging operation should be decorated with `@continuationToken`. Similarly, the response property that contains the continuation token value should also be decorated with `@continuationToken`.

1. Continuation token in query parameter and response body.

<ClientTabs>

```typespec
@list
op listWithPage(@query @continuationToken continuationToken?: string): UserList;

model User {
  id: string;
  name: string;
}

model UserList {
  @pageItems
  value: User[];

  @continuationToken
  continuationToken?: string;
```

## Advanced

### Parameterized next links (against guidelines)

:::danger
Parameterized next links are against guidelines. Please don't follow this unless explicitly told to do so
:::

In very rare cases, there are cases of next links that require parameterization. These cases exist outside of the Azure guidelines for paging, but must be supported for legacy reasons.

In cases like this, you may use the special scalar type `Azure.Core.Legacy.parameterizedNextLink`. You can specify which parameters must be reformatted into the next link. Your emitted SDK will handle the reformatting based on the tsp definition

```tsp
model ListCertificateOptions {
  includePending?: string;
}
model Certificate {
  name: string;
}
model Page {
  @pageItems items: Certificate[];
  @nextLink nextLink: Azure.Core.Legacy.parameterizedNextLink<[
    ListCertificateOptions.includePending
  ]>;
}
```

## Paging Legacy Decorators

:::caution
The following decorators are in the `Azure.ClientGenerator.Core.Legacy` namespace and should only be used for legacy services with explicit approval. New services should use standard paging patterns.
:::

### `@markAsPageable`

The `@markAsPageable` decorator forces a regular operation to be treated as a pageable operation. The response model must contain a property annotated with `@pageItems`.

<ClientTabs>

```typespec title="main.tsp"
import "@typespec/http";

using TypeSpec.Http;

@service(#{ title: "Item Service" })
namespace ItemService;

model Item {
  id: string;
  name: string;
}

model ItemListResult {
  @pageItems
  items: Item[];

  nextLink?: string;
}

@route("/items")
@get
op listItems(): ItemListResult;
```

```typespec title="client.tsp"
import "./main.tsp";
import "@azure-tools/typespec-client-generator-core";

using Azure.ClientGenerator.Core.Legacy;

@@markAsPageable(ItemService.listItems);
```

```python
class ItemServiceClient:
    def list_items(self, **kwargs: Any) -> ItemPaged[Item]: ...
```

```csharp
public partial class ItemServiceClient
{
    public virtual Pageable<Item> GetItems(CancellationToken cancellationToken = default);
    public virtual AsyncPageable<Item> GetItemsAsync(CancellationToken cancellationToken = default);
}
```

```typescript
export function listItems(
  context: Client,
  options?: ListItemsOptionalParams,
): PagedAsyncIterableIterator<Item>;
```

```java
public final class ItemServiceClient {
    public PagedIterable<Item> listItems();
}
```

```go
func (client *ItemServiceClient) NewListItemsPager(options *ItemServiceClientListItemsOptions) *runtime.Pager[ItemServiceClientListItemsResponse]
```

</ClientTabs>

### `@disablePageable`

The `@disablePageable` decorator prevents a list operation from being treated as pageable. The response is returned as the full model instead of being unwrapped into a paged iterator of items.

<ClientTabs>

```typespec title="main.tsp"
import "@typespec/http";

using TypeSpec.Http;

@service(#{ title: "Item Service" })
namespace ItemService;

model Item {
  id: string;
  name: string;
}

model ItemListResult {
  @pageItems
  items: Item[];

  nextLink?: string;
}

@route("/items")
@get
@list
op listItems(...Item): ItemListResult;
```

```typespec title="client.tsp"
import "./main.tsp";
import "@azure-tools/typespec-client-generator-core";

using Azure.ClientGenerator.Core.Legacy;

@@disablePageable(ItemService.listItems);
```

```python
# Returns the full model instead of a paged iterator
class ItemServiceClient:
    def list_items(self, *, id: str, name: str, **kwargs: Any) -> ItemListResult: ...
```

```csharp
// Returns the full ItemListResult model, not a Pageable<Item>
public partial class ItemServiceClient
{
    public virtual Response<ItemListResult> GetItems(string id, string name, CancellationToken cancellationToken = default);
    public virtual async Task<Response<ItemListResult>> GetItemsAsync(string id, string name, CancellationToken cancellationToken = default);
}
```

```typescript
// Returns the full ItemListResult model, not a PagedAsyncIterableIterator<Item>
export function listItems(
  context: Client,
  id: string,
  name: string,
  options?: ListItemsOptionalParams,
): Promise<ItemListResult>;
```

```java
// Returns the full ItemListResult model, not a PagedIterable<Item>
public final class ItemServiceClient {
    public ItemListResult listItems(String id, String name);
}
```

```go
// Returns the full response, not a Pager
func (client *ItemServiceClient) ListItems(ctx context.Context, id string, name string, options *ItemServiceClientListItemsOptions) (ItemServiceClientListItemsResponse, error)
```

</ClientTabs>

### `@nextLinkVerb`

The `@nextLinkVerb` decorator specifies the HTTP verb (`"GET"` or `"POST"`) to use when following next-link pagination URLs. By default, next-link requests use `GET`. Use this decorator when the service requires `POST` for pagination. This decorator only affects the internal implementation of paging and does not change the public API surface.

<ClientTabs>

```typespec title="main.tsp"
import "@typespec/http";

using TypeSpec.Http;

@service(#{ title: "Item Service" })
namespace ItemService;

model Item {
  id: string;
  name: string;
}

model ItemListResult {
  @pageItems
  items: Item[];

  @nextLink
  nextLink?: string;
}

@route("/items")
@get
@list
op listItems(...Item): ItemListResult;
```

```typespec title="client.tsp"
import "./main.tsp";
import "@azure-tools/typespec-client-generator-core";

using Azure.ClientGenerator.Core.Legacy;

@@nextLinkVerb(ItemService.listItems, "POST");
```

</ClientTabs>
