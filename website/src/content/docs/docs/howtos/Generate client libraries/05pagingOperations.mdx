This doc details what emitters will generate for paging operations.

## Using next link to indicate how to get the next page

Next link is an absolute url returned by the paging operation, which indicates how to get the next page.
If the response does not return a next link, it indicates the last page of results.
Next link should be annotated in the response model with `@nextLink`.

There are two ways to indicate a paging operation with `@nextLink`:

1. Use `@list`, `@nextLink` and `@items`

<ClientTabs>

```typespec
@list op listWithPage(): UserList;

model User {
  id: string;
  name: string;
}

model UserList {
  @pageItems
  value: User[];

  @nextLink
  nextLink?: url;
}
```

```python
class User(_model_base.Model):
    id: str = rest_field()
    name: str = rest_field()

def list_with_page(self, **kwargs: Any) -> ItemPaged["_models.User"]:
    ...
```

```csharp
public virtual Pageable<User> ListWithPage(CancellationToken cancellationToken = default);
```

```typescript
export interface ListWithPageOptionalParams extends OperationOptions {}
// JS CodeGen api layer
export function listWithPage(
  context: Client,
  options: ListWithPageOptionalParams = { requestOptions: {} },
): PagedAsyncIterableIterator<User>;

// JS CodeGen classical client layer
export class TestServiceClient {
  listWithPage(
    options: ListWithPageOptionalParams = { requestOptions: {} },
  ): PagedAsyncIterableIterator<User>;

```

## Using continuation token to indicate how to get the next page

A continuation token is a string returned by a paging operation, which is used as a parameter value for the paging operation to get the next page.
If the response does not return a continuation token, it indicates the last page of results.
The request parameter that corresponds to the continuation token value in the paging operation should be decorated with `@continuationToken`. Similarly, the response property that contains the continuation token value should also be decorated with `@continuationToken`.

1. Continuation token in query parameter and response body.

<ClientTabs>

```typespec
@list
op listWithPage(@query @continuationToken continuationToken?: string): UserList;

model User {
  id: string;
  name: string;
}

model UserList {
  @pageItems
  value: User[];

  @continuationToken
  continuationToken?: string;
}
```

## Advanced

### Parameterized next links (against guidelines)

:::danger
Parameterized next links are against guidelines. Please don't follow this unless explicitly told to do so
:::

In very rare cases, there are cases of next links that require parameterization. These cases exist outside of the Azure guidelines for paging, but must be supported for legacy reasons.

In cases like this, you may use the special scalar type `Azure.Core.Legacy.parameterizedNextLink`. You can specify which parameters must be reformatted into the next link. Your emitted SDK will handle the reformatting based on the tsp definition

```tsp
model ListCertificateOptions {
  includePending?: string;
}
model Certificate {
  name: string;
}
model Page {
  @pageItems items: Certificate[];
  @nextLink nextLink: Azure.Core.Legacy.parameterizedNextLink<[
    ListCertificateOptions.includePending
  ]>;
}
```

## Legacy: Overriding next link HTTP verb

:::caution
`@nextLinkVerb` is legacy functionality from `Azure.ClientGenerator.Core.Legacy`. Use it only when the service fetches subsequent pages using `POST` instead of `GET`. This is against guidelines for new services.
:::

By default, paging operations fetch subsequent pages with an HTTP `GET` request on the next link URL. When a service requires a `POST` request for subsequent pages, use `@Azure.ClientGenerator.Core.Legacy.nextLinkVerb("POST")`.

<ClientTabs>

```typespec
import "@typespec/http";
import "@azure-tools/typespec-client-generator-core";

using Http;
using Azure.ClientGenerator.Core;
using Azure.ClientGenerator.Core.Legacy;

@service(#{ title: "Widget Service" })
namespace WidgetService;

model Widget {
  id: string;
  name: string;
}

model WidgetPage {
  @pageItems
  widgets: Widget[];

  @nextLink
  nextLink?: url;
}

/** List widgets — subsequent pages are fetched via POST */
@nextLinkVerb("POST")
@list
@route("/widgets")
@post
op listWidgets(): WidgetPage;
```

```python
class WidgetServiceClient:
    def list_widgets(self, **kwargs: Any) -> ItemPaged["Widget"]:
        """List widgets — subsequent pages are fetched via POST.

        :return: An iterator like instance of Widget
        :rtype: ~azure.core.paging.ItemPaged[~widgetservice.models.Widget]
        """
        ...
```

```csharp
public partial class WidgetServiceClient
{
    public virtual Pageable<Widget> GetWidgets(CancellationToken cancellationToken = default);
    public virtual AsyncPageable<Widget> GetWidgetsAsync(CancellationToken cancellationToken = default);
}
```

```typescript
export class WidgetServiceClient {
  listWidgets(
    options: ListWidgetsOptionalParams = { requestOptions: {} },
  ): PagedAsyncIterableIterator<Widget>;
}
```


## Legacy: Disabling pageable behavior

:::caution
`@disablePageable` is legacy functionality from `Azure.ClientGenerator.Core.Legacy`. Use it only when an operation matches standard paging patterns (e.g. has a `@nextLink` field or is decorated with `@list`) but should NOT be treated as pageable. This is rare and should only be used when explicitly instructed.
:::

By default, operations that match standard paging patterns are generated as pageable (returning iterators). Use `@Azure.ClientGenerator.Core.Legacy.disablePageable` to prevent an operation from being treated as pageable — the response will be returned as the raw paged model type rather than an iterator.

<ClientTabs>

```typespec
import "@typespec/http";
import "@azure-tools/typespec-client-generator-core";

using Http;
using Azure.ClientGenerator.Core;
using Azure.ClientGenerator.Core.Legacy;

@service(#{ title: "Widget Service" })
namespace WidgetService;

model Widget {
  id: string;
  name: string;
}

model WidgetPage {
  @pageItems
  widgets: Widget[];

  @nextLink
  nextLink?: url;
}

/**
 * List all widgets — returns the full paged model, not an iterator.
 * Even though the response has a nextLink, paging is disabled.
 */
@disablePageable
@list
@route("/widgets/all")
@get
op getAllWidgets(): WidgetPage;
```

```python
class WidgetServiceClient:
    def get_all_widgets(self, **kwargs: Any) -> WidgetPage:
        """List all widgets. Returns the raw WidgetPage model (not an iterator).

        :return: WidgetPage
        :rtype: ~widgetservice.models.WidgetPage
        """
        ...
```

```csharp
public partial class WidgetServiceClient
{
    // Returns WidgetPage directly, not Pageable<Widget>
    public virtual Response<WidgetPage> GetAllWidgets(CancellationToken cancellationToken = default);
    public virtual async Task<Response<WidgetPage>> GetAllWidgetsAsync(CancellationToken cancellationToken = default);
}
```

```typescript
export class WidgetServiceClient {
  getAllWidgets(
    options: GetAllWidgetsOptionalParams = { requestOptions: {} },
  ): Promise<WidgetPage>;
}
```

