# Azure Resource Manager Documentation Update Knowledge Base

## Build Environment

- The project requires Node.js >= 22.0.0 to build and run `pnpm regen-docs`.
- If Node 22 is unavailable, fix both the `.tsp` source and the generated reference doc directly to keep them in sync.

## Documentation Structure

- **Getting started** (`getstarted/azure-resource-manager/`): Manually maintained tutorial pages.
- **How-to guides** (`howtos/ARM/`): Manually maintained topic guides.
- **Reference docs** (`libraries/azure-resource-manager/reference/`): Auto-generated via `pnpm regen-docs` from `packages/typespec-azure-resource-manager/`. Output only goes to the `reference/` subdirectory.
- **Rule docs** (`libraries/azure-resource-manager/rules/`): Manually maintained with ❌/✅ examples. NOT auto-generated by `regen-docs`.

## Naming Patterns

- The idiomatic way to define ARM resource name parameters is `...ResourceNameParameter<MyResource>` (spread pattern). The older manual `@key`/`@segment`/`@path`/`name` pattern should not be used in docs.
- Custom key/segment names use named template args: `...ResourceNameParameter<Res, KeyName = "myKey", SegmentName = "mySegment">`.

## Common Documentation Issues Found

- The subscription-based resource section in `resource-type.md` incorrectly said "Tenant resources use..." — copy-paste error from the Tenant section above it.
- Rule file `no-response-body.md` had its title set to `no-empty-model` — these are two different rules. The title must match the file name and actual rule name.
- Rule file `unsupported-type.md` had its title as plural `unsupported-types` and namespace as `@azure-tools/typespec-azure-core` instead of `@azure-tools/typespec-azure-resource-manager`.
- `ArmResourceActionNoContentAsync` is deprecated in favor of `ArmResourceActionNoResponseContentAsync`. The getting-started step04 previously listed the deprecated template without noting this.

## Decorator Doc Comments

- The `@dev` tag in `.tsp` doc comments is intentional on template interfaces — it prevents the description from leaking into template instantiations. Never convert `@dev` to regular doc comments.

## Linting Rules

- There are 34 registered linting rules in `linter.ts`, all with severity: warning.
- One additional rule (`arm-legacy-operations-discourage`) exists in the source but is not registered in `linter.ts`.
- Some rule doc filenames don't include the `arm-` prefix (e.g., `delete-operation-response-codes.md` for rule `arm-delete-operation-response-codes`). This is an existing convention in the repo, not a bug.
