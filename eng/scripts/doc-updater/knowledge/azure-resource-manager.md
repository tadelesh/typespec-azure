# Azure Resource Manager Documentation Knowledge Base

## Build & Regeneration

- The reference docs under `website/src/content/docs/docs/libraries/azure-resource-manager/reference/` are auto-generated by running `pnpm regen-docs` from `packages/typespec-azure-resource-manager/`. Never edit these directly — fix the source `.tsp` doc comment and regenerate.
- The rules docs under `website/src/content/docs/docs/libraries/azure-resource-manager/rules/` are NOT auto-generated. Edit them directly.
- The linter reference file `reference/linter.md` IS auto-generated by `regen-docs`. It lists correct rule names and links to rule doc files.
- Before `regen-docs` works, you must build `@typespec/tspd` and then `@azure-tools/typespec-azure-resource-manager`: `cd core && pnpm -r --filter "@typespec/tspd..." build` then `pnpm -r --filter "@azure-tools/typespec-azure-resource-manager..." build`.
- `gen-extern-signature` (part of the build) regenerates `generated-defs/*.ts` and `README.md` from doc comments. These files will change whenever TSP doc comments are modified.

## Deprecated Aliases (models.tsp)

The following aliases exist in `lib/models.tsp` and are marked with `#deprecated`. When updating examples, always use the `*Property` suffix version:

| Deprecated Alias                | Current Model                           |
| ------------------------------- | --------------------------------------- |
| `ManagedServiceIdentity`        | `ManagedServiceIdentityProperty`        |
| `ManagedSystemAssignedIdentity` | `ManagedSystemAssignedIdentityProperty` |
| `EntityTag`                     | `EntityTagProperty`                     |
| `ResourceKind`                  | `ResourceKindProperty`                  |
| `ResourcePlan`                  | `ResourcePlanProperty`                  |
| `ResourceSku`                   | `ResourceSkuProperty`                   |
| `ManagedBy`                     | `ManagedByProperty`                     |

The `Encryption` alias (→ `EncryptionProperty`) exists but is NOT formally `#deprecated`.

## Deprecated Operation Templates

| Deprecated                        | Replacement                               |
| --------------------------------- | ----------------------------------------- |
| `ResourceOperations`              | `TrackedResourceOperations`               |
| `ArmResourceDeleteAsync`          | `ArmResourceDeleteWithoutOkAsync`         |
| `ArmResourceCreateOrUpdateSync`   | `ArmResourceCreateOrReplaceSync`          |
| `ResourceDeleteAsync` (interface) | Not used — the base interface is internal |

Note: `ArmResourceCreateOrUpdateAsync` is NOT deprecated — it's a valid template for update semantics (vs. replace).

## Rule Documentation Conventions

- Rule doc frontmatter `title` must exactly match the registered rule name (e.g., `arm-delete-operation-response-codes`, not `delete-operation-response-codes`).
- The "Full name" code block must use the correct package namespace: `@azure-tools/typespec-azure-resource-manager/<rule-name>`.
- File names in `rules/` don't always include the `arm-` prefix (historical), but the title and full name must be accurate.

## TSP Doc Comment Patterns

- `@dev` comments are intentional — they prevent descriptions from becoming defaults on template instantiations. Never remove or convert them.
- `@param target` is implicit in decorator signatures — do not document it in doc comments.
- `@template` tags should only document parameters that actually exist in the template signature.
- The `Foundations.ArmUpdateOperation` template has 4 type params: `HttpParameters`, `BodyParameter`, `Response`, `ErrorResponse`. No `RequestBody` parameter.

## Samples Location

Canonical ARM samples are in `packages/samples/specs/resource-manager/`. Key subdirectories:

- `resource-types/tracked/` — standard tracked resource pattern
- `resource-types/proxy/` — child/proxy resources
- `resource-types/extension/` — extension resources
- `resource-types/singleton/` — singleton resources
- `resource-types/tenant/` — tenant-scoped resources
- `resource-types/private-endpoints/` — private endpoint connection pattern
- `resource-types/nsp/` — network security perimeter pattern
- `resource-common-properties/managed-identity/` — managed identity spread pattern
- `resource-common-properties/encryption/` — CMK/encryption pattern

## Common Types Versioning

The `Azure.ResourceManager.CommonTypes.Versions` enum has: v3, v4, v5, v6. Most modern services should use v5 or v6.

## ResourceNameParameter Usage

The canonical way to define a resource name property is: `...ResourceNameParameter<Resource>` (uses defaults) or `...ResourceNameParameter<Resource, KeyName = "customName", SegmentName = "customSegment">`. Do NOT use raw `@key`/`@segment`/`@path` in documentation examples.
