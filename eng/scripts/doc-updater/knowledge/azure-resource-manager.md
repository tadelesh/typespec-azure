# Azure Resource Manager Documentation Knowledge Base

## Build & Tooling

- Requires Node.js >= 22 for building packages due to `engines.node` constraint in core packages.
- Use `pnpm -r --filter "@azure-tools/typespec-azure-resource-manager..." build` to build the ARM package and its dependencies.
- Use `pnpm regen-docs` from `packages/typespec-azure-resource-manager/` to regenerate reference docs after editing `.tsp` doc comments.
- The `regen-docs` command outputs to `website/src/content/docs/docs/libraries/azure-resource-manager/reference/` only. The `rules/` directory is NOT auto-generated by `regen-docs`.
- The build also regenerates `generated-defs/Azure.ResourceManager.ts` and `README.md` from `.tsp` doc comments, so fixing comments in `.tsp` files propagates to three places: reference docs, generated-defs, and README.

## Rule Documentation

- Rule docs live in `website/src/content/docs/docs/libraries/azure-resource-manager/rules/` and are hand-maintained, NOT auto-generated.
- Rule frontmatter `title` must exactly match the registered rule name from `packages/typespec-azure-resource-manager/src/rules/*.ts`.
- The "Full name" code block in each rule doc must use the package `@azure-tools/typespec-azure-resource-manager/` followed by the registered rule name.
- Rule URLs are defined in each rule's `.ts` source file and are used by `linter.md` (auto-generated) to link to rule docs. File names in `rules/` must match the URL path segment.
- Common pitfall: rule names may start with `arm-` prefix but the doc file name and URL may not include it. The frontmatter title and full name MUST still include the prefix.

## Envelope Properties

- Envelope property models follow a `*Property` naming convention: `ManagedServiceIdentityProperty`, `ManagedSystemAssignedIdentityProperty`, `ResourceSkuProperty`, `EntityTagProperty`, `ResourcePlanProperty`, `ResourceKindProperty`, `ManagedByProperty`, `ExtendedLocationProperty`.
- The old names without `Property` suffix (`ManagedServiceIdentity`, `ResourceSku`, `EntityTag`, `ResourcePlan`, `ResourceKind`, `ManagedBy`) are deprecated aliases.
- `ExtendedLocationProperty` is a current non-deprecated envelope property that enables extended location support.

## Doc Comment Patterns in .tsp Files

- `@dev` comments are intentional — they prevent descriptions from becoming defaults on template instantiations. Never remove or convert them.
- Operation template doc comments commonly use `@template Resource the resource being <verb>` pattern. Watch for copy-paste errors where the verb doesn't match the operation (e.g., "patched" for a list operation, "updated" for a create operation).
- `@doc` string interpolation uses `{name}` syntax — watch for missing closing braces like `{name `.
- The `@param` tags in decorator doc comments must match actual function parameters. Ghost parameters (referencing non-existent params) should be removed.

## Deprecated APIs to Watch For

- `ArmResourceCreateOrUpdateAsync` → `ArmResourceCreateOrReplaceAsync`
- `ArmResourceCreateOrUpdateSync` → `ArmResourceCreateOrReplaceSync`
- `ArmResourceDeleteAsync` → `ArmResourceDeleteWithoutOkAsync`
- `@locationResource` → `@parentResource(ArmLocationResource<...>)`
- Foundation type aliases: `ArmResource`, `TrackedResourceBase`, `ProxyResourceBase`, `ExtensionResourceBase`, `ResourceSkuType`, `ResourcePlanType` — all deprecated.
- Identity types: `ManagedIdentityProperties` → `ManagedServiceIdentity` → `ManagedServiceIdentityProperty` (double deprecation chain).
