# Azure Resource Manager Documentation Knowledge Base

## Build and Regeneration

- Build the package with `pnpm -r --filter "@azure-tools/typespec-azure-resource-manager..." build`
- Regenerate reference docs with `pnpm regen-docs` from `packages/typespec-azure-resource-manager/`
- The `regen-docs` script outputs to `website/src/content/docs/docs/libraries/azure-resource-manager/reference/`
- Rule reference docs under `rules/` are NOT auto-generated by `regen-docs` — they are manually maintained
- The `generated-defs/` and `README.md` files are regenerated during the build (`gen-extern-signature`)
- Format files with `pnpm format:dir <directory>` before committing

## Documentation Structure

- **Getting started** (`getstarted/azure-resource-manager/step00-05.md`): beginner tutorial
- **How-to guides** (`howtos/ARM/*.md`): topic-focused guides for experienced users
- **Reference docs** (`libraries/azure-resource-manager/reference/`): auto-generated from `.tsp` doc comments — never edit directly
- **Rule docs** (`libraries/azure-resource-manager/rules/`): manually maintained, one file per linting rule

## Rule Doc Format

Each rule doc uses this frontmatter and heading format:

```md
---
title: <rule-short-name>
---

\`\`\`text title="Full name"
@azure-tools/typespec-azure-resource-manager/<rule-short-name>
\`\`\`
```

The `title` attribute on the code block must be `title="Full name"` (with double quotes). A prior batch of files used incorrect `title=- Full name-` syntax.

## Common Pitfalls

- The `@doc()` template string `{name}` requires a closing brace: `@doc("Get a {name}", Resource)`. Missing braces (e.g., `{name SomeText}`) will produce broken interpolation.
- Envelope property spread models were renamed with a `Property` suffix (e.g., `ManagedServiceIdentity` → `ManagedServiceIdentityProperty`). The old names exist as deprecated aliases. Always use the `*Property` versions in docs.
- The `@armProviderNamespace` decorator only accepts `providerNamespace?: valueof string`. It does NOT accept a `libraryNamespaces` parameter — that was a ghost `@param` in the doc comment.
- The decorator `@armProviderNameValue` was incorrectly documented as `@armResourceType` in its own doc comment.
- Linting rules are registered in `src/linter.ts`. The `arm-legacy-operations-discourage` rule exists as a source file but is NOT registered in the linter.
- The rule `arm-resource-operation` (in `core-operations.ts`) was previously referenced in docs as `arm-resource-operation-missing-decorator`, which does not exist.
