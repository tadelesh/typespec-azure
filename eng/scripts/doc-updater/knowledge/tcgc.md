# TCGC Documentation Update Knowledge Base

## Build System

- Use `npx pnpm` to run pnpm commands (corepack pnpm not directly available)
- Must build core packages first before TCGC: `npx pnpm -r --filter "typespec-client-generator-core..." build`
- The `tspd` tool lives at `core/packages/tspd` and must be built before running `regen-docs`
- To regen reference docs: build tspd, build TCGC, then run `npx pnpm regen-docs` from TCGC package dir

## TSP Decorator File Patterns

- `decorators.tsp` contains all main decorators in `Azure.ClientGenerator.Core` namespace
- `legacy.tsp` contains legacy decorators in `Azure.ClientGenerator.Core.Legacy` namespace
- Doc comments in these files are the source for auto-generated reference docs at `reference/decorators.md`
- After editing doc comments, run `pnpm regen-docs` to update `reference/decorators.md`
- Running `regen-docs` also updates `README.md` and `generated-defs/*.ts` files

## Guideline.md

- The `guideline.md` file references `SdkClientType.children` and `SdkClientType.parent` for client hierarchy
- The internal `SdkClient` type uses `subClients` (in `interfaces.ts:112`), but the public `SdkClientType` uses `children` (in `interfaces.ts:228`)
- The `@moveTo` decorator was renamed to `@clientLocation` — all references should use `@clientLocation`

## Howto Docs Structure

- Files are numbered 00-12 in `website/src/content/docs/docs/howtos/Generate client libraries/`
- All `<ClientTabs>` blocks must be generated by the `@doc-example-generator` skill
- Language order in ClientTabs: typespec, python, csharp, typescript, java, go

## Spector Specs

- Spector specs live in `packages/azure-http-specs/specs/azure/client-generator-core/`
- Each spec needs: `main.tsp` (with @scenario/@scenarioDoc) and `mockapi.ts`
- After adding specs, run: build → validate-mock-apis → cspell → format → regen-docs
- `spec-summary.md` is auto-generated — never edit manually
- Scenario names follow pattern: `Scenarios.<Namespace_With_Underscores>_<OperationName>`

## Common Doc Comment Issues Found

- `@paramAlias` example incorrectly passed model directly to `@@clientInitialization` instead of wrapping in `{parameters: ...}`
- `@override` second example had garbled comment combining two different outcomes
- `@markAsLro` had typo "operatio" instead of "operation"

## Decorator Coverage in Spector

Decorators WITH Spector specs: @access, @alternateType, @apiVersion, @clientDefaultValue,
@clientInitialization, @clientLocation, @clientName (client/naming/), @client (client/structure/),
@deserializeEmptyStringAsNull, @flattenProperty, @hierarchyBuilding, @nextLinkVerb, @override,
@usage, @paramAlias (in client-initialization/), @responseAsBool, paging, LRO

Decorators without dedicated Spector specs (most don't need them since they affect code gen style, not HTTP behavior):
@convenientAPI, @protocolAPI, @scope, @clientDoc, @clientOption, @clientNamespace (covered by client/namespace/),
@clientApiVersions, @useSystemTextJsonConverter, @markAsLro, @markAsPageable, @disablePageable

## Doc Example Generator

- Skill directory: `.github/skills/doc-example-generator/`
- Uses its own `package.json` and `tspconfig.yaml`
- For C# emitter: must create empty `metadata.json` in output dir before compilation
- Java emitter warns about missing azure-sdk-for-java folder — this is expected and non-fatal
- All five language emitters (Python, C#, TypeScript, Java, Go) should produce output in sandbox
