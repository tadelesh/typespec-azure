# TCGC Documentation Update Knowledge Base

## Build and Regen Commands

- To build TCGC: `npx pnpm -r --filter "@azure-tools/typespec-client-generator-core..." build`
- To regen reference docs: `npx pnpm -C packages/typespec-client-generator-core regen-docs` (requires tspd and TCGC both built)
- To build azure-http-specs: `npx pnpm -r --filter "@azure-tools/azure-http-specs..." build`
- To validate mock APIs: `cd packages/azure-http-specs && npx pnpm validate-mock-apis`
- To regen spec summary: `cd packages/azure-http-specs && npx pnpm regen-docs`
- The `core/` directory contains the TypeSpec compiler and tspd; it may need to be built first if `dist/` doesn't exist.

## Decorator File Structure

- Main decorators: `packages/typespec-client-generator-core/lib/decorators.tsp` (Azure.ClientGenerator.Core namespace)
- Legacy decorators: `packages/typespec-client-generator-core/lib/legacy.tsp` (Azure.ClientGenerator.Core.Legacy namespace)
- Generated defs auto-updated by `gen-extern-signature` during build in `generated-defs/`
- Reference docs at `website/src/content/docs/docs/libraries/typespec-client-generator-core/reference/decorators.md` — auto-generated by `regen-docs`, never edit directly

## Doc Example Generator

- The @doc-example-generator skill requires a `package.json` and `tspconfig.yaml` from `.github/skills/doc-example-generator/`
- Run `npm install --legacy-peer-deps` in the temp directory
- Compile with `npx tsp compile .` (or `npx tsp compile client.tsp` if using augment decorators)
- For C# emitter: create empty `tsp-output/@azure-typespec/http-client-csharp/metadata.json` before compilation
- Go emitter does NOT support @responseAsBool (errors with "didn't find HTTP response for kind boolean")
- Java emitter warns about missing 'azure-sdk-for-java' SDK folder but still generates output
- @clientApiVersions: C# and TS include all versions; Java and Python may only show service versions

## Common Pitfalls

- The `@paramAlias` example must use inline decorator syntax (`@paramAlias("alias")` on the model property), NOT augment syntax — the augment syntax shown in older docs was incorrect.
- The `@@clientInitialization` augment must use `{parameters: Model}` wrapper, not just the model directly.
- The `@override` examples must reference the override operation with its full namespace path (e.g., `MyCustomizations.myOperationCustomization`).
- In the `@override` first example, the `Params` model should be defined in the service namespace (matching the test pattern), not the customizations namespace.
